# Log Analyzer (C + Python)

Инструмент для высокопроизводительного парсинга серверных логов и генерации визуальных HTML-отчётов. Проект сочетает скорость языка **C** при построчной обработке файлов с гибкостью **Python** для аналитики и построения графиков.

## Быстрый старт и установка

Склонируйте репозиторий и настройте виртуальное окружение Python:

```bash
git clone https://github.com/rfv234/log-analyzer.git
cd log-analyzer
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Как пользоваться (Инструкция для пользователя)

### 1. Тестовый запуск (на примере из коробки)
Чтобы сразу проверить работу программы на встроенном тестовом логе (`data/server.log`), выполните одну команду:
```bash
make run
```
Эта команда автоматически скомпилирует C-парсер, обработает лог, построит графики и соберёт итоговый отчёт.

### 2. Анализ собственного лог-файла
Передайте путь к вашему лог-файлу через параметр `LOG`:
```bash
make run LOG=/путь/к/вашему/файлу.log
```

**Требуемый формат строк в лог-файле:**
Программа ожидает текстовый лог, где каждая строка начинается с даты, времени, уровня события (`INFO`, `WARNING` или `ERROR`) и текста сообщения:
```text
2026-11-16 10:01:22 INFO User login successful
2026-11-16 10:02:15 WARNING High memory usage detected (84%)
2026-11-16 10:03:05 ERROR Database connection timeout
```
*(Строки нестандартного формата не ломают программу — они автоматически учитываются в категории `UNKNOWN`).*

### 3. Просмотр и пересылка отчёта
После завершения работы откройте готовый файл **`results/report.html`** в любом браузере:
```bash
xdg-open results/report.html   # Linux
open results/report.html       # macOS
```
Все графики встроены прямо внутрь `report.html` (в формате Base64), поэтому этот файл полностью автономен — его можно переслать в Telegram или открыть на другом устройстве без исходной папки проекта.

### 4. Очистка временных файлов
Чтобы удалить скомпилированный бинарник и сгенерированные отчёты:
```bash
make clean
```

## Архитектура проекта

Конвейер разделён на два независимых этапа, связанных через JSON-контракт (`results/results.json`):

1. **C-ядро (`c_engine/main.c`):**
   - Построчное чтение лог-файлов (`fgets` + `sscanf`) с защитой от переполнения буфера.
   - Подсчёт событий по уровням (`INFO`, `WARNING`, `ERROR`, `UNKNOWN`).
   - Группировка уникальных ошибок и поминутной активности с использованием динамической памяти (`realloc` / `free`).
   - Сортировка ошибок по частоте и экспорт результатов в `results/results.json`.
2. **Python-модуль (`python/`):**
   - `analyzer.py` — валидация JSON-схемы, расчёт процентного соотношения уровней и поиск пиковой минуты сбоев.
   - `vizualization.py` — генерация диаграмм распределения уровней и таймлайна ошибок через **Matplotlib**.
   - `report.py` — сборка автономного отчёта `results/report.html` в тёмной теме.

## Структура репозитория

```text
log-analyzer/
├── c_engine/
│   └── main.c              # Парсер логов и генератор JSON на C
├── python/
│   ├── analyzer.py         # Валидация и аналитика данных
│   ├── vizualization.py    # Построение графиков (Matplotlib)
│   └── report.py           # Генератор итогового HTML-отчёта
├── data/
│   └── server.log          # Пример входного лог-файла
├── Makefile                # Автоматизация сборки и запуска
└── requirements.txt        # Зависимости Python
```
